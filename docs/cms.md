# 写作后台与图片存储

## 写作入口

- **本地**：`pnpm dev:cms` 同时启动站点和本地代理，然后打开 `http://localhost:4321/admin/`，选择本地登录。也可以分两个终端运行 `pnpm dev` 与 `pnpm cms:local`。
- **线上**：每页页脚右侧有一个“写作”链接，指向 `/admin/`，用 GitHub 账号登录。`cms.enabled: false` 时既不生成后台，也不显示这个链接。

本地代理只在 loopback 地址启用，不要把代理端口暴露到公网。它直接读写工作目录，不模拟 GitHub 的分支草稿流程；`draft: true` 的内容仍被博客构建排除。

文章分成 Markdown 和 MDX 两个入口，都递归读取 `content/posts/`。文件路径只管理存放位置，不决定分类或公开链接。Markdown 普通内容支持可视化与源码模式；含公式、Mermaid、HTML 或 MDX 的内容自动使用源码模式。MDX 始终使用源码编辑；后台不执行任意 MDX 导入，复杂内容请用本地站点检查。

编辑器预览使用 Decap 渲染，不等同完整 Astro 页面。不要通过可视化编辑器重新序列化未经验证的复杂 Markdown。

## 界面语言与外观

后台界面是简体中文。语言由 `src/lib/cms-config.ts` 的 `locale` 决定；Decap 自带的中文包比它自身版本旧，缺少批注、列表控件、图片多选等 47 条文案，这些由 `public/admin/locale.js` 补齐，所以不会再出现中英混排。要换成别的语言，把 `locale` 改成 `de`、`ja` 等 `decap-cms-locales` 里的名字即可，缺的条目会回退到英文。

外观由 `public/admin/theme.css` 覆盖，沿用博客的纸白、陶土色与衬线标题。**注意**：Decap 用的是构建时生成的哈希类名，没有稳定的样式钩子，这份样式靠元素结构和它自己的 CSS 变量选择器实现，Decap 升级后可能需要跟着调整。自定义控件（相册图片列表、R2 图片库）用的是自己的类名（`v7-*`），不受影响。

`scripts/prepare-admin.mjs` 在构建时把 Decap 分发包和全部语言包复制到 `public/admin/vendor/`，该目录不提交。

## 多位作者

1. 每位作者都需要一个 GitHub 账号，并对站点仓库有**写权限**（仓库 Settings → Collaborators 邀请）。
2. 在后台“作者、分类、标签与友链 → 作者”添加作者资料，得到一个稳定 ID。
3. 文章可以写多位作者；相册可指定作者，单张图片还可以单独覆盖。

登录校验在服务端进行：没有写权限的 GitHub 账号拿不到编辑令牌。

## 相册

相册文件在 `content/albums/`，后台对应“相册”集合。每个相册有标题、slug、日期、简介、作者、相册标签、封面图片 ID 和一组图片。

每张图片的字段：

| 字段             | 说明                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| 图片、替代文本   | 必填。替代文本描述画面，供读屏和加载失败时使用。                        |
| 图片 ID          | 分享链接 `#photo-ID` 的一部分，上传时自动生成；发布后不要修改。         |
| 类型             | 照片或创作。                                                            |
| 标题、说明、日期 | 可选。                                                                  |
| 地点             | 纯文字，例如“杭州 · 西湖”。不记录坐标。                                 |
| 标签             | 从“照片标签”中选择，与文章标签分开维护。                                |
| 作者             | 留空沿用相册作者，相册也没写时用默认作者。                              |
| 许可             | 留空沿用站点默认（`media.license`）；选 `custom` 时填写自定义许可文字。 |
| 摄影参数         | 相机、镜头、焦距、光圈、快门、ISO、胶片、后期软件。                     |
| 创作信息         | 设备、软件或工具、媒介。                                                |
| 宽度、高度、主色 | 上传时自动填写，用于瀑布流排版和加载前的占位色。                        |

照片标签在“作者、分类、标签与友链 → 照片标签”维护，每个标签有稳定 ID 与中英文名称。未登记的标签、作者或许可会让构建失败，并提示具体原因。

站点默认许可在“站点设置 → media.license”，可选：保留所有权利、CC BY 4.0、CC BY-NC 4.0、CC BY-NC-SA 4.0、CC0 1.0、custom（配合 `media.licenseText`）。

## 上传流程：压缩并移除 EXIF

两种存储模式都在浏览器里先处理图片，原图不会离开你的电脑：

1. 只接受 JPEG、PNG、WebP，文件不超过 20 MB、不超过 4000 万像素。HEIC 等格式请先导出为 JPEG。
2. 读取 EXIF，只用于填写表单（见下节）。
3. 用 canvas 重新编码为 WebP。**EXIF、GPS、XMP 等元数据全部丢弃**，只保留浏览器写入的 sRGB 色彩配置。
4. GitHub 模式生成一张长边不超过 2400 px 的图片；R2 模式生成 480/960/1600/2400 四种宽度。
5. 计算主色，作为页面加载前的占位色。

因此仓库和 R2 里只有网页版本，**不保存摄影原图，原图请自行归档**。SVG 与 GIF 按原样上传，不做处理。

## EXIF 自动填写

上传后，相册图片表单的空白字段会自动填入相机、镜头、焦距、光圈、快门、ISO、后期软件和拍摄日期（只精确到天）。

- 只填写**空着**的字段，你手动输入的内容不会被覆盖；填入后仍可随意修改。
- 图片列表上方有一个勾选框，可以随时关闭，选择会记在当前浏览器里。
- 全站关闭：把 `site.config.json` 的 `media.exifPrefill` 设为 `false`，勾选框也随之隐藏。
- GPS 坐标永远不会读取或写入。

## 线上登录与发布（Cloudflare Pages Functions）

GitHub 登录与 R2 图片接口由 `functions/api/` 提供，和站点同域名、一起部署，不需要单独的 Worker，也不涉及跨域。

- `/api/auth` 发起 GitHub OAuth，`/api/callback` 校验 OAuth state，并检查登录账号对仓库的写权限。
- `/api/media` 仅在 R2 模式使用：每次请求都校验同源来源和仓库写权限。

具体配置步骤见[部署说明](deployment.md)。`cms.authURL` 留空即可；只有把登录服务放在别的域名时才需要填写。

生产后台使用 Decap editorial workflow：保存草稿写入独立分支，发布时才合并到发布分支。内容中的 `draft` 是额外的构建排除标记；发布前必须关闭并保存，后台会阻止发布仍带有该标记的内容。未来日期仍需到期后重新构建，没有自动定时发布。

公开仓库的草稿分支也公开。本主题仓库只放演示内容；真实的私密草稿应放在使用者自己的私有仓库里。请关闭托管平台对草稿分支的公开预览构建。

## 图片模式 A：GitHub 仓库（默认）

`media.provider: "github"`。图片经过上面的压缩流程后，由 Decap 内置媒体库上传到 `public/images/uploads/`，公开路径为 `/images/uploads/`，随文章一起提交。

本地图片在构建时还会由 Astro 生成更小尺寸的响应式 WebP，所以列表缩略图不会下载 2400 px 的大图。

## 图片模式 B：Cloudflare R2

`media.provider: "r2"`，并在 Pages 项目里绑定 R2 bucket（绑定名 `MEDIA`）、设置 `PUBLIC_MEDIA_URL`。图片库使用当前 GitHub 登录令牌访问 `/api/media`。R2 凭据通过绑定提供，不进入浏览器。后台支持上传、选择已有图片和分页浏览；没有提供删除接口，避免误删仍被引用的图片。

上传包上限 16 MB。选择 R2 图片后，保存时自动写入尺寸、主色与 `srcset`；正文里插入的是最大网页版本 URL。R2 模式需要 GitHub 登录，本地代理模式下不可用。R2 免费额度有上限，本主题不承诺零费用。

公开图片 URL 持有者可以访问图片，即使对应内容尚未发布。图片键随机生成；媒体列表只对有写权限的后台用户开放。

## 配置与维护

- `cms.enabled: false` 不生成后台页面和页脚入口；博客仍可以直接编辑文件维护。
- `features` 控制模块页面、导航、首页预览、后台入口与站点地图；`features.albums` 同时控制 `/albums/` 与 `/photos/`。
- 站点配置、作者、分类与照片标签变动后需要重新构建。后台保存配置后，刷新已部署的后台才能拿到新选项。
- 切换图片存储不会搬迁旧文件；本地 URL 与外部 URL 可以共存。
- 作者、分类和照片标签 ID 应保持稳定；删除前先清理引用。分类父子关系不能成环。
- Decap 使用固定依赖版本并在本地复制其资源；普通博客页面不加载 CMS。
- 后台样式依赖 Decap 的类名结构，升级 Decap 后请重新检查 `public/admin/theme.css`。
